## 1. 项目背景与愿景

### 1.1 一句话定位

**FlowPlan** 是一款手机端 TODO（待办事项）管理应用，未来将由 AI 辅助管理任务：
用户用自然语言告诉 AI"帮我安排今天的三件事"，AI 自动拆解、排期、提醒，用户只需要执行。

### 1.2 为什么先做基础框架版（本版本范围）

AI 能力（自然语言理解、任务拆解、自动排期）是**锦上添花**，而 TODO 的**增删改查 + 本地存储**是**地基**。
真实项目的开发节奏是：

```
地基不牢 → 后面每加一个功能都要返工
地基扎实 → AI 接入只是"插一个模块"的事
```

所以本版本（v0.1）只做 TODO 的地基，但**架构上必须为 AI 预留好接口**。

### 1.3 最终愿景（未来版本，不在本次范围）

| 版本 | 内容 |
|------|------|
| v0.1（本次） | 基础 TODO：增删改查、完成/未完成、优先级、本地持久化 |
| v0.2 | AI 助手：对话窗口，自然语言添加任务 |
| v0.3 | AI 排期：根据截止日期/优先级自动安排每日计划 |
| v0.4 | 云端同步：多设备数据同步 |
| v1.0 | 正式发布 |

## 2. 用户画像与使用场景

### 2.1 目标用户

- **小明**，大学生：每天有课程作业、社团活动、个人计划，需要一个轻量的 TODO 记录工具。
- **小红**，上班族：任务多且杂，希望未来能用 AI 把"任务清单"自动整理成"今日计划"。

### 2.2 核心使用场景

1. 小明打开 App，看到今天的任务列表。
2. 小明点击"+"，输入任务内容"完成数学作业"，选择优先级"高"，保存。
3. 任务出现在列表中，小明完成后勾选，任务变为"已完成"。
4. 小明想删除一条任务，左滑或长按删除。
5. 小明想修改任务内容，点进去编辑。
6. **（未来）** 小明对 AI 说："把周三前的任务按重要性排一下"，AI 自动重排。

### 3.2 任务（Todo）数据模型

一个任务在数据层面长什么样？这是整个 App 最核心的概念，我们用表格定义清楚：

| 字段 | 类型 | 示例 | 说明 |
|------|------|------|------|
| id | String (UUID) | `a3f8-...` | 唯一标识，相当于 Python 里的主键 |
| title | String | 完成数学作业 | 任务标题（必填） |
| description | String | 第三章习题 1-10 | 备注（可选） |
| priority | enum | high / medium / low | 优先级：高/中/低 |
| isCompleted | bool | false | 是否已完成 |
| createdAt | DateTime | 2026-09-01 10:00 | 创建时间 |
| updatedAt | DateTime | 2026-09-01 10:05 | 最后修改时间 |
| dueDate | DateTime? | null | 截止日期（本版可选，为 v0.3 排期预留） |

> 💡 **和 Python 的类比**：这就像你定义一个 `dataclass`：
> ```python
> @dataclass
> class Todo:
>     id: str
>     title: str
>     description: str = ""
>     priority: str = "medium"   # high/medium/low
>     is_completed: bool = False
>     created_at: datetime
>     updated_at: datetime
>     due_date: datetime | None = None
> ```
> 后面你会看到 Dart 版本的写法——几乎一一对应。

## 5. 技术选型（为什么选这些）

> 技术选型是真实项目里最需要"讲道理"的部分。每个选择都要能回答"为什么不用别的？"

| 选型点 | 选择 | 备选方案 | 选择理由 |
|--------|------|----------|----------|
| 跨平台框架 | Flutter | React Native | 你已装好 Flutter；Dart 语法对 Python 学习者友好 |
| 语言 | Dart 3.x | — | Flutter 官方语言 |
| 状态管理 | Riverpod | Provider / Bloc | 现代主流、可测试、依赖注入方便、社区活跃 |
| 本地数据库 | sqflite (SQLite) | Hive / Isar | **你会 Python 的 sqlite3，SQL 概念可迁移**；关系型适合任务查询 |
| 架构模式 | feature-first + 分层 | MVC / MVVM 单层 | 功能隔离清晰，AI 模块可独立扩展 |
| UI 风格 | Material 3 | Cupertino | Google 系默认，组件丰富，适合快速开发 |

### 5.1 状态管理为什么选 Riverpod（重要决策）

TODO App 的痛点：**多个页面要共享同一份任务数据**（列表页新增 → 编辑页修改 → 列表页要刷新）。

- 不用状态管理：每个页面自己存数据，页面间同步靠"回调传参"，项目一复杂就乱成麻。
- Riverpod 的方案：数据放在一个**全局可访问的"状态容器"**里，任何页面读写它，**改一处，所有引用处自动刷新**。

> 💡 **和 Python 的类比**：Riverpod 的 `Provider` 有点像 Python 里的**单例 + 观察者模式**：
> ```python
> # 伪代码：全局唯一的"任务仓库"
> todo_repo = TodoRepository()          # 全局单例
> observers = []                        # 谁关心数据变化
> def add_todo(t): todo_repo.add(t); [o.update() for o in observers]
> ```
> Riverpod 把"单例""订阅""自动刷新"这些事封装好了，你不用自己写。

### 5.2 为什么用 sqflite 而不是 Hive

- Hive 是 NoSQL 键值存储，像 Python 的 `json` 文件 + 字典。
- sqflite 是 SQLite，像 Python 标准库的 `sqlite3`。

选 sqflite 的理由：
1. **概念迁移**：你会 `SELECT * FROM todos WHERE ...`，这部分知识完全复用。
2. **查询能力强**：未来按日期、优先级筛选任务，SQL 一条语句搞定。
3. **关系扩展**：未来任务关联"项目""标签"，关系型数据库天然支持。

## 6. 架构设计（预览）

本版采用 **feature-first 架构**（按功能分包）+ **三层分离**（每个功能内部分 domain / data / presentation）：

```
lib/
├── main.dart              # 程序入口（类比 Python 的 if __name__ == "__main__")
├── app.dart               # App 根组件（主题、路由配置）
├── core/                  # 全局共享：主题、常量、通用工具
│   ├── theme/             # 主题配置
│   └── constants/         # 常量定义
└── features/              # 按功能划分（一个功能一个文件夹）
    └── todo/
        ├── domain/        # 领域层：Todo 模型 + 抽象接口（最稳定，不依赖任何外部库）
        ├── data/          # 数据层：SQLite 实现（对接 sqflite）
        ├── application/   # 应用层：业务逻辑（对接 Riverpod 状态）
        └── presentation/  # 表现层：UI 页面 + 状态管理
```

> 💡 **为什么这样分层？** 一句话：**让"会变的"和"不变的"分开**。
> - `domain`：TODO 的"定义"（什么是任务）——永远不变。
> - `data`：任务"存在哪里"——今天 SQLite，明天可能换云端，只动这一层。
> - `presentation`：任务"长什么样"——今天列表，明天加日历视图，只动这一层。
> - **AI 接入点**：未来在 `application` 层加一个 `AIService`，调用 `TodoRepository` 接口操作任务，presentation 完全不用改。

详细架构说明见下一份文档《02-技术架构设计》。

### 验收演示场景（M4 手动测试脚本）

1. 打开 App → 看到空列表 + "今日任务"标题 + 统计"已完成 0 / 共 0"。
2. 点右下角 ➕ → 输入"买牛奶"，优先级"中" → 保存 → 列表出现"买牛奶"。
3. 勾选"买牛奶" → 文字变灰加删除线，统计变"已完成 1 / 共 1"。
4. 点进"买牛奶" → 改标题为"买牛奶和面包" → 保存 → 列表更新。
5. 左滑删除 → 确认 → 列表清空。
6. 杀掉 App 重新打开 → 数据还在（持久化成功）。
7. 切换"全部/未完成/已完成"筛选 → 显示正确。
