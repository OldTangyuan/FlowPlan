## 2. 国内网络优化（重要！）

### 2.1 为什么需要镜像

Flutter 的依赖下载源在国外（pub.dev、maven.google.com），国内访问很慢甚至超时。
flutter doctor 显示 `maven.google.com` 超时就是这个原因。

### 2.2 配置方法（推荐，永久生效）

在系统环境变量中设置两个镜像地址（以腾讯云镜像为例，也可以选阿里云/清华）：

| 变量名 | 值 |
|--------|-----|
| `PUB_HOSTED_URL` | `https://pub.flutter-io.cn` |
| `FLUTTER_STORAGE_BASE_URL` | `https://storage.flutter-io.cn` |

> 临时生效（当前终端窗口）：
> ```powershell
> $env:PUB_HOSTED_URL = "https://pub.flutter-io.cn"
> $env:FLUTTER_STORAGE_BASE_URL = "https://storage.flutter-io.cn"
> ```

### 2.3 Android 构建镜像（gradle 依赖）

Android 构建还要配置 gradle 镜像。在 `android/build.gradle.kts` 的
`allprojects.repositories` 里添加阿里云镜像（见下文"构建问题"）。

## 3. 踩坑记录（本次开发实际遇到的）

> 真实项目里，把这些坑记下来就是团队的知识库。每个坑都附上"原因 + 解法"。

### 坑 1：flutter 命令卡住不动 / 超时

**现象**：`flutter --version` 运行几分钟无输出，最后超时。

**排查过程**（这就是真实项目的排查套路）：
1. 先确认 Flutter 装没装：`where flutter` → 找到了。
2. 直接跑 `dart --version` → 正常输出（说明 SDK 本身没坏）。
3. 直接跑 `flutter_tools.snapshot` → 报错：
   ```
   Flutter failed to open a file at "...\bin\cache\lockfile"
   ```
4. 测试写文件 `Set-Content C:\Programing\_test.txt` → 拒绝访问。

**根因**：Flutter 工具运行时需要在 `C:\Programing\flutter\bin\cache` 写入
lockfile（防止多个 flutter 同时操作缓存），但该目录对当前进程不可写。

**解法**：以完整文件访问权限运行 flutter 命令。
> 在 DSH 环境中是给命令授予完整权限；在普通终端里通常不会有这个问题，
> 如果你遇到，检查目录权限或用管理员终端。

**经验**：flutter 卡住 → 90% 是"写缓存"失败或"网络"问题。先看报错再动手。

### 坑 2：pub.dev 依赖下载慢

**现象**：`flutter pub add` 下载 flutter_riverpod 等包耗时数分钟。

**解法**：配置镜像（见 2.2），耐心等待首次下载（之后有缓存就快了）。

### 坑 3：SQLite 排序 SQL 报错 "no such column"

**现象**：单元测试报错：
```
no such column: "high" - should this be a string literal in single-quotes?
```

**根因**：SQLite 里**字符串字面量必须用单引号** `'high'`，
双引号 `"high"` 会被当成"列名"！我最初写了：
```sql
CASE priority WHEN "high" THEN 0 ...   -- ❌ 双引号 = 列名，报错
CASE priority WHEN 'high' THEN 0 ...   -- ✅ 单引号 = 字符串
```

**经验**：SQL 的引号规则和 Python/Dart 完全不同，写 SQL 时特别注意。

### 坑 4：Riverpod 3.x 与旧教程 API 不同

**现象**：`flutter analyze` 报错 `StateNotifierProvider isn't defined`。

**根因**：网上大量教程是 Riverpod 2.x 的写法。Riverpod 3.0 起
`StateNotifier` / `StateNotifierProvider` 被**移除**，官方推荐新的 `Notifier`。

**解法**：改用 Riverpod 3 的 `Notifier` + `NotifierProvider`：
```dart
// ❌ 旧写法（Riverpod 2.x）
class TodoController extends StateNotifier<TodoListState> { ... }
final todoControllerProvider = StateNotifierProvider<TodoController, TodoListState>(...);

// ✅ 新写法（Riverpod 3.x）
class TodoController extends Notifier<TodoListState> {
  @override
  TodoListState build() { ... }   // 状态在 build() 里创建
}
final todoControllerProvider =
    NotifierProvider<TodoController, TodoListState>(TodoController.new);
```

**经验**：**查文档一定要看版本！** 版本不对，教程全废。
Flutter 生态更新快，务必以官方文档 + 你安装的版本为准。

### 坑 5：测试数据互相污染

**现象**：数据库测试 `count()` 期望 0，实际 4（上一个测试的数据还在）。

**根因**：所有测试共用同一个磁盘数据库文件，测试之间数据没清理。

**解法**：给 `TodoDatabase` 加"注入路径"的能力，测试时用内存数据库：
```dart
// 生产：默认路径
final db = TodoDatabase();
// 测试：内存数据库，每个测试独立
final db = TodoDatabase(databasePath: inMemoryDatabasePath);
```

**经验**：**测试隔离**是测试的第一原则。这个改动顺带让架构更好——
数据源支持依赖注入，这正是"可测试性设计"的实践。

### 坑 6：DateTime 精度导致测试不稳定

**现象**：`updatedAt 修改后应该变化` 的测试失败。

**根因**：两次调用 `DateTime.now()` 在同一毫秒内，时间戳相同，
断言"时间变了"不成立。

**解法**：测试里用固定的过去时间构造对象，断言 `updatedAt.isAfter(past)`。

**经验**：**测试里不要依赖"真实时间"**，用固定值，否则测试结果不稳定。

### 坑 7：Android 构建失败 —— sqlite3 原生库下载中断

**现象**：`flutter run` 构建 15 分钟后失败：
```
Building assets for package:sqlite3 failed.
HttpException: Connection closed while receiving data,
  uri = https://release-assets.githubusercontent.com/.../libsqlite3.x64.android.so
```

**根因**：
1. `sqflite_common_ffi`（我们测试用的包）依赖 `sqlite3` 包。
2. Dart 3 的 **native assets（原生资产）机制**：构建时会对所有依赖包
   运行构建钩子（hook），sqlite3 的钩子会从 **GitHub releases** 下载
   各平台的预编译 SQLite 库。
3. 国内网络访问 GitHub release-assets 不稳定，下载中断 → 构建失败。

**排查思路**（真实项目的排查套路）：
1. 看报错 → 发现是下载 `libsqlite3.x64.android.so` 失败（网络问题）。
2. 找到 sqlite3 包的钩子代码，确认下载 URL 和缓存机制：
   - 下载 URL：`https://github.com/simolus3/sqlite3.dart/releases/download/sqlite3-3.5.2/<文件名>`
   - 缓存目录：`.dart_tool/hooks_runner/shared/sqlite3/build/download-<hash前8位>/`
   - **缓存命中条件**：目标文件存在且 SHA256 与预期一致 → 跳过下载。

**解法**（手动放置缓存文件）：
```powershell
# 1. 下载（可重试几次）
Invoke-WebRequest -Uri '<下载URL>' -OutFile 'libsqlite3.so.tmp'

# 2. 校验 SHA256 必须与包内记录的完全一致
Get-FileHash 'libsqlite3.so.tmp' -Algorithm SHA256

# 3. 改名为目标文件名，放到缓存目录
Move-Item 'libsqlite3.so.tmp' '<缓存目录>\libsqlite3.so'
```
钩子发现缓存文件 hash 正确，就会直接复用，不再下载。

**经验**：
- 国内 Flutter 开发，构建失败 80% 是**网络**问题（下载中断）。
- 报错里有 URL → 先看 URL 是哪里的 → 判断是代码问题还是网络问题。
- native assets 这类"构建期下载"的依赖，遇到网络问题时
  **手动放缓存文件**是标准解法。
