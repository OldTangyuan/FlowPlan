```dart

void main() {
```

### 逐行讲解

| 代码 | 作用 | Python 类比 |
|------|------|-------------|
| `void main()` | 程序入口函数 | `if __name__ == "__main__":` 里的逻辑 |
| `WidgetsFlutterBinding.ensureInitialized()` | 初始化 Flutter 与系统的绑定（sqflite 需要平台通道，必须先初始化） | 启动前先 `import sqlite3` 并建立连接 |

| `runApp(...)` | 把根组件挂到屏幕上，启动应用 | Flask 的 `app.run()` |

### 📌 架构位置

```
main.dart（入口）
   └── ProviderScope（Riverpod 总开关）
          └── FlowPlanApp（根组件）
```

## 2. `lib/app.dart` —— App 根组件

### 完整代码

```dart
class FlowPlanApp extends ConsumerWidget {
  const FlowPlanApp({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    return MaterialApp(
      title: AppConstants.appName,
      theme: AppTheme.light(),
      debugShowCheckedModeBanner: false,
      home: const TodoListPage(),
    );
  }
}
```

### 关键概念讲解

**1. 什么是 Widget（组件）？**
Flutter 里一切皆组件——文字是组件、按钮是组件、页面是组件、App 本身也是组件。
组件像乐高积木，层层嵌套搭出整个界面。

> 💡 **和 Python 的类比**：最接近的是 Django 模板的 include 嵌套，
> 或者 Flask 的 render_template 拼接。但 Flutter 的组件更强大：
> 组件 = 界面 + 行为 + 数据，一个组件就是一个完整的小单元。

**2. `ConsumerWidget` 是什么？**
Riverpod 提供的组件基类。普通的 `StatelessWidget` 没有 `ref`，
而 `ConsumerWidget` 的 `build` 方法多了一个 `ref` 参数，
可以用它读写全局状态。

**3. `MaterialApp` 是什么？**
Flutter 的"App 外壳"，负责：标题、主题、路由（页面跳转）、
国际化等全局配置。

> 💡 **和 Python 的类比**：MaterialApp ≈ Django 的 settings.py +
> urls.py + 全局模板。所有全局配置都在这。

**4. `home:` 是什么？**
App 启动后显示的第一个页面。这里是 `TodoListPage`（任务列表页）。

## 5. `lib/features/todo/domain/models/todo.dart` —— 任务模型（核心！）

这是整个应用最重要的文件之一。分三部分讲解。

### 5.1 优先级枚举

```dart
enum TodoPriority {
  high('high', '高', 3),
  medium('medium', '中', 2),
  low('low', '低', 1);

  final String value;      // 存储值（数据库里存这个）
  final String label;      // 显示名（界面显示这个）
  final int sortOrder;     // 排序权重

  const TodoPriority(this.value, this.label, this.sortOrder);
}
```

> 💡 **和 Python 的类比**：Python 的 `Enum` 只能存一个值，
> Dart 的枚举可以存**多个字段**——相当于：
> ```python
> class TodoPriority(Enum):
>     HIGH = ("high", "高", 3)
>     MEDIUM = ("medium", "中", 2)
>     LOW = ("low", "低", 1)
> ```

### 5.2 Todo 模型

```dart
class Todo {
  final String id;
  final String title;
  final String description;
  final TodoPriority priority;
  final bool isCompleted;
  final DateTime createdAt;
  final DateTime updatedAt;
  final DateTime? dueDate;

  const Todo({ required this.id, required this.title, ... });
}
```

**核心设计：所有字段都是 `final`（不可变）**

> ⚠️ 这是 Dart 和 Python 最大的思维差异！
> - Python：`todo.title = "新标题"` 直接改。
> - Dart：字段是 final，改不了，只能用 `copyWith` 生成**新对象**。
>
> 好处：对象一旦创建就不会被偷偷改坏。多线程/异步环境下特别安全。

### 5.3 三个关键方法

**`Todo.create(...)` 工厂构造**——新建任务的入口：
```dart
factory Todo.create({required String title, ...}) {
  final now = DateTime.now();
  return Todo(
    id: const Uuid().v4(),  // 自动生成 UUID
    createdAt: now,
    updatedAt: now,
    ...
  );
}
```
> 💡 Python 类比：`@classmethod` 里的 `cls(...)`。
> UI 层只管传标题，id/时间戳自动生成，省心。

**`copyWith(...)` 复制修改**——修改任务的唯一方式：
```dart
Todo copyWith({String? title, ...}) {
  return Todo(
    id: id,                    // 没传的保持原值
    title: title ?? this.title,
    updatedAt: DateTime.now(), // 自动刷新修改时间
    ...
  );
}
```
> 💡 Python 类比：`dataclasses.replace(todo, title="新标题")`。

**`toMap()` / `fromMap()` 序列化**——对象与数据库的桥梁：
```dart
Map<String, dynamic> toMap() {
  return {
    'id': id,
    'is_completed': isCompleted ? 1 : 0,  // SQLite 没有 bool，用 0/1
    'created_at': createdAt.toIso8601String(), // 时间存字符串
    ...
  };
}
```
> 💡 Python 类比：`to_dict()` / `from_dict()`。
> 时间用 ISO8601 字符串存，Dart/Python/任何语言都能解析。

## 6. `lib/features/todo/domain/repositories/todo_repository.dart` —— 抽象接口（架构灵魂）

### 完整代码

```dart
abstract interface class TodoRepository {
  Future<List<Todo>> getAll();
  Future<Todo?> getById(String id);
  Future<void> add(Todo todo);
  Future<void> update(Todo todo);
  Future<void> delete(String id);
  Future<void> deleteCompleted();
  Future<int> count();
}
```

### 为什么这是"架构灵魂"

这个文件**只定义接口，不写实现**。它像一个合同：
"任何想存取任务的东西，必须提供这些方法。"

- UI 只认这个合同，不关心背后是 SQLite 还是云端。
- **未来 AI 也按这个合同操作任务**——AI 服务调用 `add/update/delete`，
  界面完全不用改。

> 💡 **和 Python 的类比**：抽象基类（ABC）：
> ```python
> class TodoRepository(ABC):
>     @abstractmethod
>     async def get_all(self) -> list[Todo]: ...
> ```

**`abstract interface class` 语法说明**（Dart 3 新特性）：
- `abstract`：不能直接实例化，只能被实现。
- `interface`：只能 `implements`（实现），不能 `extends`（继承）。
  比 Python 的 ABC 更严格，防止误用。

**`Future<T>` 说明**：
数据库操作是耗时的，不能阻塞 UI。`Future<T>` 表示"将来会返回 T"。
调用时用 `await` 等待结果。

> 💡 **和 Python 的类比**：`Future<T>` ≈ `asyncio.Task`。
> `await` 的语法几乎一模一样！

## 7. `lib/features/todo/data/datasources/todo_database.dart` —— SQLite 数据源

### 核心：打开数据库 + 建表

```dart
Future<Database> _open() async {
  final path = databasePath ?? p.join(await getDatabasesPath(), 'flowplan.db');
  return openDatabase(
    path,
    version: AppConstants.dbVersion,
    onCreate: (db, version) async {
      await db.execute('''
        CREATE TABLE todos (
          id TEXT PRIMARY KEY,
          title TEXT NOT NULL,
          description TEXT NOT NULL DEFAULT '',
          priority TEXT NOT NULL DEFAULT 'medium',
          is_completed INTEGER NOT NULL DEFAULT 0,
          created_at TEXT NOT NULL,
          updated_at TEXT NOT NULL,
          due_date TEXT
        )
      ''');
    },
    onUpgrade: (db, oldVersion, newVersion) async { /* 预留 */ },
  );
}
```

### 关键概念

**1. `onCreate` 和 `onUpgrade`（数据库版本管理）**
- 第一次打开数据库（版本 1）→ 执行 `onCreate` 建表。
- 以后升级（版本 2, 3...）→ 执行 `onUpgrade` 做迁移。
- **这是"面向未来"的体现**：现在把钩子留好，v0.2 加字段时
  改 `dbVersion` 为 2，在 `onUpgrade` 里写 `ALTER TABLE`，老用户数据不丢。

**2. 依赖注入路径**
```dart
final String? databasePath;  // 可传可不传
```
- 生产：不传 → 用应用专属目录。
- 测试：传 `inMemoryDatabasePath` → 内存数据库，互不污染。

**3. 排序 SQL（注意单引号！）**
```sql
ORDER BY is_completed ASC,
  CASE priority WHEN 'high' THEN 0 WHEN 'medium' THEN 1 ELSE 2 END,
  created_at DESC
```
- 未完成在前 → 已完成。
- 同状态下优先级高的在前。
- 最后新的在前。
- ⚠️ SQLite 字符串必须单引号 `'high'`，双引号会被当成列名（坑 3）！

> 💡 **和 Python 的类比**：这段 SQL 和 `sqlite3` 的完全一样，
> 你在 Python 里学的 SQL 知识直接迁移。

## 9. `lib/features/todo/application/todo_controller.dart` —— 业务逻辑中枢（第二核心）

这个文件是状态管理的核心，也是初学者最需要理解的部分。分四块讲。

### 9.1 仓库 Provider（依赖注入）

```dart
final todoRepositoryProvider = Provider<TodoRepository>((ref) {
  return TodoRepositoryImpl(TodoDatabase());
});
```

**讲解**：
- `Provider`：Riverpod 的"全局单例工厂"。第一次被访问时创建，之后复用。
- 返回类型是**接口** `TodoRepository`，实际是 SQLite 实现。
- 未来换实现，只改这一行。

> 💡 **和 Python 的类比**：
> ```python
> _repo = None
> def get_repo():
>     global _repo
>     if _repo is None:
>         _repo = TodoRepositoryImpl(TodoDatabase())
>     return _repo
> ```

### 9.2 状态类

```dart
class TodoListState {
  final List<Todo> todos;       // 任务列表
  final TodoFilter filter;      // 当前筛选
  final bool isLoading;         // 是否加载中
  final String? error;          // 错误信息
  // copyWith 方法...
  int get totalCount => todos.length;          // 统计
  int get completedCount => ...;
}
```

> 💡 **和 Python 的类比**：dataclass，把页面需要的所有数据打包成一个对象。

### 9.3 控制器（Riverpod 3 的 Notifier）

```dart
class TodoController extends Notifier<TodoListState> {
  late final TodoRepository _repository;

  @override
  TodoListState build() {
    _repository = ref.watch(todoRepositoryProvider);
    Future.microtask(loadTodos);  // 首次加载
    return const TodoListState(todos: [], isLoading: true);
  }
  // 操作方法：loadTodos / addTodo / updateTodo / toggleTodo / deleteTodo ...
}
```

**⚠️ Riverpod 3 的关键变化**（坑 4）：
- 旧版（2.x）：`StateNotifier<T>`，状态在构造函数传入。
- 新版（3.x）：`Notifier<T>`，状态在 `build()` 里创建。

**`build()` 的角色**：
1. 建立依赖（`ref.watch` 仓库）。
2. 返回初始状态。
3. 依赖变化时自动重建（响应式的来源）。

**操作方法模式**（以 addTodo 为例）：
```dart
Future<bool> addTodo({required String title, ...}) async {
  final todo = Todo.create(title: title, ...);  // 1. 造对象
  await _repository.add(todo);                   // 2. 存数据库
  await loadTodos();                             // 3. 重新加载（UI 自动刷新）
  return true;
}
```

> 💡 **和 Python 的类比**：像 Django 的 service 层：
> ```python
> async def add_todo(self, title, priority):
>     todo = Todo.create(title=title, priority=priority)
>     await self.repo.add(todo)
>     await self.load_todos()
> ```

### 9.4 控制器 Provider

```dart
final todoControllerProvider =
    NotifierProvider<TodoController, TodoListState>(TodoController.new);
```

- UI 通过 `ref.watch(todoControllerProvider)` 拿**状态**（自动刷新）。
- UI 通过 `ref.watch(todoControllerProvider.notifier)` 拿**控制器**（调用方法）。
- `.notifier` 是 Riverpod 3 的语法，表示"这个 Provider 的操作者"。

### 10.3 `presentation/pages/todo_list_page.dart` —— 列表页（主界面）

**核心：ConsumerWidget + ref.watch**

```dart
class TodoListPage extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final controller = ref.watch(todoControllerProvider.notifier); // 控制器
    final state = ref.watch(todoControllerProvider);               // 状态
    ...
  }
}
```

**响应式刷新的魔法**：
- `ref.watch(...)` 订阅状态。
- 任何时候 `state` 变化（增删改、筛选），`build` 自动重新执行，界面自动更新。
- **这就是"数据一变，界面自动变"**，不用手动写刷新逻辑。

> 💡 **和 Python 的类比**：观察者模式。Riverpod 替你实现了
> "数据变化 → 通知所有订阅者 → 刷新界面"。

**页面的四种状态**（_buildBody 处理）：
1. `isLoading` → 转圈（CircularProgressIndicator）
2. `error != null` → 错误提示 + 重试按钮
3. 空列表 → 友好提示（"还没有任务，点击右下角开始吧"）
4. 有数据 → ListView 展示

> 💡 空状态设计很重要：用户第一次打开 App 看到的就是它，要友好。

### 10.4 `presentation/pages/todo_edit_page.dart` —— 新增/编辑页

**关键设计：一个页面两种模式**

```dart
class TodoEditPage extends ConsumerStatefulWidget {
  final Todo? initialTodo;  // null = 新增；非 null = 编辑
}
```

- `initialTodo == null` → 新增模式，表单为空。
- `initialTodo != null` → 编辑模式，表单预填。

> 💡 **和 Python 的类比**：Flask 里新增和编辑共用同一个模板：
> ```python
> @app.route("/todo/new")
> def new(): return render_template("form.html", todo=None)
> @app.route("/todo/<id>/edit")
> def edit(id): return render_template("form.html", todo=get(id))
> ```

**为什么用 ConsumerStatefulWidget？**
- 需要**本地状态**：用户正在输入的文字（TextEditingController）。
- 需要**全局状态**：保存时调用 controller。
- StatefulWidget 提供本地状态，Consumer 提供 ref 访问全局。

**保存逻辑**：
```dart
if (_isEditing) {
  final updated = widget.initialTodo!.copyWith(title: title, ...);
  await controller.updateTodo(updated);   // 编辑：更新
} else {
  await controller.addTodo(title: title, ...);  // 新增
}
Navigator.of(context).pop();  // 保存成功，返回上一页
```

```dart
container = ProviderContainer(overrides: [
  todoRepositoryProvider.overrideWithValue(TodoRepositoryImpl(db)),
]);
```
- `overrides`：Riverpod 的依赖替换能力——测试时注入假数据源。
- 这就是依赖注入设计带来的测试便利。

## 12. 数据流全景回顾

把整个 App 串起来看一次"添加任务"：

```
用户点击"新增任务"按钮
  → TodoListPage 调用 _openAddPage → 跳转 TodoEditPage
  → 用户输入标题，点"保存"
  → TodoEditPage 调 controller.addTodo(title)
  → TodoController（application）创建 Todo 对象
  → 调 _repository.add(todo)    ← 接口（domain）
  → TodoRepositoryImpl（data）转发
  → TodoDatabase 执行 INSERT SQL  ← SQLite
  → 数据库写入成功
  → loadTodos() 重新查询
  → state 更新（todos 变化）
  → Riverpod 通知所有 ref.watch 的 UI
  → TodoListPage 的 build 自动重新执行
  → 新任务出现在列表里 ✅
```

**每一环都解耦，每一环都可替换。这就是分层架构的价值。**
