## 1. 普通功能扩展指南

### 1.1 加一个新字段（比如"标签 tag"）

**场景**：想让任务支持打标签（"工作""生活""学习"）。

**改动 4 处**（每处都有注释指引）：

| 步骤 | 文件 | 改什么 |
|------|------|--------|
| 1 | `domain/models/todo.dart` | 加字段 `final String tag;` + 加进 `copyWith` + 加进 `toMap`/`fromMap` |
| 2 | `data/datasources/todo_database.dart` | 数据库版本 1→2，`onUpgrade` 里写 `ALTER TABLE todos ADD COLUMN tag TEXT` |
| 3 | `application/todo_controller.dart` | `addTodo` 加参数 |
| 4 | `presentation/pages/todo_edit_page.dart` | 表单加输入框 |

**关键点**：改数据库要动 `dbVersion`！这是"用户升级 App 数据不丢"的保障。

> 💡 这就是分层的好处：**只改 4 个地方，而且每一处都是明确的**。
> 不做架构的话，改一个字段可能要翻遍十几个文件还怕漏。

### 1.2 加一个筛选条件（比如"只看高优先级"）

| 步骤 | 文件 | 改什么 |
|------|------|--------|
| 1 | `application/todo_controller.dart` | `TodoFilter` 枚举加一个值 |
| 2 | `presentation/widgets/todo_filter_bar.dart` | 加一个 ButtonSegment |
| 3 | `application/todo_controller.dart` | `filteredTodos` 的 switch 加一个 case |

### 1.3 加一个页面（比如"统计报表页"）

| 步骤 | 文件 | 改什么 |
|------|------|--------|
| 1 | `presentation/pages/` 新建 `stats_page.dart` | 新页面 |
| 2 | `presentation/pages/todo_list_page.dart` | 加一个入口按钮（比如 AppBar 图标）跳转 |
| 3 | 如果统计需要新数据 | 在 `TodoListState` 加字段，`loadTodos` 里算好 |

### 1.4 加通知提醒（v0.2 功能）

用 Flutter 的 `flutter_local_notifications` 包：
1. `pubspec.yaml` 加依赖。
2. `application/` 新建 `notification_service.dart`。
3. `TodoController.addTodo` 里（或独立服务里）检查 `dueDate`，到点推送。

**架构上不需要大改**——notification 属于 application 层的新服务。

## 2. AI 接入路线图（核心章节）

### 2.1 总体思路

AI 管理 TODO = **AI 调用我们已经写好的那些方法**。

```
用户对 AI 说："帮我安排明天三件事"
        │
        ▼
AI 服务（application 层新增）
        │  1. 调大模型 API 理解自然语言
        │  2. 解析出结构化任务（标题、优先级、截止日期）
        ▼
TodoRepository 接口（已存在！）
        │  3. 调用 add/update/delete
        ▼
SQLite（已存在！）
```

**你发现了吗？AI 接入不需要动任何现有代码**——
因为我们一开始就把数据操作抽象成了 `TodoRepository` 接口。

### 2.2 第一步：加一个"AI 服务"抽象（本版已预留位置）

新建 `lib/features/ai/` 目录（和 todo 平级，feature-first 风格）：

```
lib/features/ai/
├── domain/
│   └── ai_service.dart          # AI 服务接口（抽象）
├── data/
│   └── ai_service_impl.dart     # 具体实现（调用某个大模型 API）
└── presentation/
    └── ai_chat_page.dart        # AI 对话页面（v0.2）
```

### 2.3 AI 服务接口设计（未来代码示例）

```dart
// lib/features/ai/domain/ai_service.dart（未来 v0.2）
abstract interface class AIService {
  /// 把自然语言解析成任务列表
  Future<List<Todo>> parseTasks(String userMessage);

  /// 根据用户指令操作任务（增/删/改/排期）
  Future<String> executeCommand(
    String userMessage,
    TodoRepository repo,   // ← 用我们的接口！
  );
}
```

**关键**：`AIService` 接收 `TodoRepository` 参数（依赖注入），
所以它天然就能增删改查任务，**完全复用现有代码**。

### 2.4 具体的大模型怎么选（给初学者的建议）

| 方案 | 优点 | 缺点 | 适合 |
|------|------|------|------|
| 云端大模型 API（OpenAI/DeepSeek/通义/文心） | 效果好、不用自己部署 | 要 API Key、要联网、要花钱 | 正式版 |
| 本地小模型（Ollama + llama3） | 免费、离线可用 | 手机性能要求高、效果一般 | 学习/原型 |

**推荐的接入模式**：先用一个简单的 `HttpClient` 调云端 API 做原型，
验证"自然语言 → 任务"的解析效果，再考虑优化。

> 💡 **和 Python 的类比**：就像你写 Python 时用 `requests` 调 API。
> Dart 里用 `http` 包：
> ```dart
> final response = await http.post(
>   Uri.parse('https://api.deepseek.com/chat/completions'),
>   headers: {'Authorization': 'Bearer $apiKey'},
>   body: jsonEncode({'messages': [...]}),
> );
> ```

### 2.6 一个完整的"AI 添加任务"调用链（未来代码预览）

```dart
// 未来 v0.2：AI 对话页的"发送"按钮
Future<void> _handleSend(String message) async {
  // 1. AI 解析自然语言 → 结构化任务
  final todos = await aiService.parseTasks(message);

  // 2. 逐个存入数据库（走我们的仓库接口！）
  final repo = ref.read(todoRepositoryProvider);
  for (final todo in todos) {
    await repo.add(todo);
  }

  // 3. 重新加载列表（界面自动刷新）
  await ref.read(todoControllerProvider.notifier).loadTodos();
}
```

**注意第 2 步**：`ref.read(todoRepositoryProvider)` 直接拿我们的仓库。
AI 和手动操作走的是**同一条数据管道**，天然一致。

## 3. 把 App 发布出去（打包）

### 3.1 生成签名 APK

```powershell
# 1. 生成签名密钥（只做一次）
keytool -genkey -v -keystore flowplan-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias flowplan

# 2. 配置 android/app/build.gradle.kts 引用密钥

# 3. 构建发布版 APK
flutter build apk --release
```

产物在 `build/app/outputs/flutter-apk/app-release.apk`，
传到手机安装即可。

### 3.2 应用商店上架

- 国内：华为应用市场、小米应用商店、OPPO/vivo 商店等（各需注册开发者账号）。
- 国外：Google Play（一次性注册费 $25）。
